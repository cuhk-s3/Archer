# Subsystem Knowledge for ValueTracking
## Elements Frequently Missed

- **Poison-Generating Flags (e.g., `samesign`, `nsw`, `ninf`, `nnan`)**: Frequently missed when analyzing instruction equivalence, PHI nodes, or pattern matching. The analysis often checks the safety of incoming operands but forgets that the instruction's or PHI node's own flags can independently generate poison, leading to invalid optimizations that unconditionally propagate poison.
- **Fast-Math Flags (FMF) and Strict IEEE-754 Semantics (e.g., `nsz`, signed zeros)**: Frequently missed during pattern matching (like min/max) and value tracking. The analysis may incorrectly apply relaxed flags from a comparison to a strict `select`, or ignore the strict behavior of signed zeros (e.g., `-0.0` divisors yielding `-Inf`), violating IEEE-754 rules.
- **UB-Implying Attributes (e.g., `noundef`, `dereferenceable`)**: Missed during speculative execution safety checks. The analysis verifies if a function is speculatable (no side effects) but ignores attached attributes that can escalate to immediate Undefined Behavior when operands are speculatively substituted.
- **Poison Elements in Vector Constants**: Missed during instruction combining and negation sinking. The analysis treats vector constants containing `poison` elements as valid mathematical identities (like zero for negation), which introduces poison into previously well-defined execution paths when operands are swapped or simplified.
- **Edge-Case Types (e.g., `i1` integers, non-scalar pointers)**: Missed in abstract domain calculations and pointer stripping. The analysis applies general rules that break down for specific types, such as integer overflow when calculating exclusive upper bounds for 1-bit integers, or returning vector-of-pointers to analyses that strictly expect scalar pointers.
- **Target-Specific Error States (e.g., `errno`)**: Missed during constant folding of standard library calls. The analysis relies on the host environment's behavior for edge-case inputs, inadvertently stripping away target-specific side effects like setting error flags.

## Patterns Not Well Handled

### Pattern 1: Speculative Execution and Operand Substitution Introducing UB/Poison
The optimization pass frequently struggles with transformations that involve speculative execution or operand substitution based on conditional equivalence. When an instruction is hoisted, or its operands are replaced with constants (e.g., substituting a pointer with `null` or a divisor with `0` based on a branch condition), the analysis often fails to re-evaluate the safety of the new construct. It assumes that because the original instruction was safe to execute, the modified instruction remains safe. This flawed reasoning transforms conditionally shielded poison or UB into unconditional poison or UB, making the optimized program more undefined than the original.

### Pattern 2: Mismatched Semantics in Higher-Level Pattern Matching
When the compiler attempts to match low-level instruction sequences (like `icmp`/`fcmp` followed by a `select`) into higher-level operations (like `smin`, `smax`, or floating-point min/max), it often mishandles semantic mismatches between the instructions. The analysis may incorrectly extract relaxed fast-math flags from the comparison and apply them to the entire pattern, or it may transform a conditional `select` that safely ignores poison into an unconditional intrinsic that propagates it. Additionally, it frequently fails to preserve strict IEEE-754 semantics regarding signed zeros during these canonicalizations, leading to incorrect sign flips.

### Pattern 3: Incomplete Cross-Operand and Edge-Case Floating-Point Logic
Value tracking for floating-point operations often relies on simplified mathematical assumptions that fail to account for complex cross-operand interactions or strict IEEE-754 edge cases. For example, the analysis may deduce that a multiplication cannot produce NaN by checking if each operand is individually "never infinity" or "never zero", completely missing the cross-operand scenario where one is zero and the other is infinity. Similarly, it fails to correctly infer properties for edge cases like division by negative zero (which yields negative infinity) or the square root of a negative number (which yields a NaN with an arbitrary sign bit), leading to incorrect constant folding and sign bit inference.

### Pattern 4: Flawed Inversion and Equivalence Analysis
The analysis often assumes that two operations are exact logical inverses or equivalents based solely on their opcodes and operands, without verifying all attached properties. Specifically, it fails to check for matching poison-generating flags. If one comparison has a flag that can produce poison under certain conditions while the other does not, they are not strict inverses. Relying on this flawed equivalence to perform optimizations, such as replacing a `select` with a logical `xor`, can unconditionally propagate poison and miscompile the program.

### Pattern 5: Improper Handling of Boundary Conditions in Abstract Domains
When computing abstract representations, such as Constant Ranges or stripping pointer casts to find underlying objects, the analysis frequently mishandles boundary conditions. For instance, when calculating the exclusive upper bound for a constant range, adding 1 to the maximum possible value causes an overflow for 1-bit (`i1`) integers, resulting in an incorrect empty range. Similarly, pointer stripping logic fails to halt correctly when encountering casts from non-scalar pointers (like vectors of pointers), passing invalid types to downstream analyses like Alias Analysis and causing unpredictable behavior.
