# Subsystem Knowledge for InstCombine
## Elements Frequently Missed

*   **Poison-Generating Flags (`nsw`, `nuw`, `exact`, `disjoint`, `inbounds`, `samesign`)**: These flags are frequently retained when instructions are reused for new folds, when operations are reassociated, or when guarding conditions (like `select` or logical AND/OR) are removed. Failing to drop these flags in the new, less-restrictive context leads to unconditional poison propagation.
*   **Fast-Math Flags (FMF) (`nnan`, `ninf`, `nsz`)**: FMFs are often incorrectly propagated from conditionally executed instructions (like a negated branch of a `select`) to unconditional instructions, or they are blindly copied rather than properly intersected when nested floating-point operations are combined.
*   **UB-Implying Attributes and Metadata (`noundef`, `dereferenceable`, `range`, `nonnull`)**: These are frequently missed (i.e., not stripped) when an instruction's execution is made speculative, when its operands are altered via demanded-bits simplification, or when an intrinsic is relaxed to return `poison`. This escalates a safe `poison` value into immediate Undefined Behavior.
*   **Special Floating-Point Values (NaN, Infinity, Signed Zero)**: The strict IEEE-754 semantics for these values are often overlooked when converting conditional negations or selections into absolute value (`fabs`), `copysign`, or min/max intrinsics, which can inadvertently alter sign bits or payload representations.
*   **`undef` and `poison` Values in Constants and Vectors**: These values are mishandled during instruction expansion (causing multiple independent evaluations of `undef`), vector deduplication, or when replacing arithmetic operations with `select`. The optimization pass often fails to recognize that `undef`/`poison` can leak into demanded lanes or cause refinement failures if not explicitly frozen.
*   **Context-Sensitive Predicates and Known Bits**: The pass sometimes relies on stale predicates after canonicalization, or computes known bits using the wrong control-flow context (e.g., applying false-branch assumptions to the true-branch of a `select`), leading to invalid simplifications.
*   **Pointer Provenance and Upper Bits**: These are ignored when replacing pointers based solely on equality comparisons, or when folding pointer comparisons into direct integer comparisons after `inttoptr` casts, leading to invalid memory accesses or the loss of truncated upper bits.

## Patterns Not Well Handled

### Pattern 1: Folding Conditional Selections (`select`) into Unconditional Operations
The optimization pass frequently attempts to fold `select` instructions (or logical AND/ORs acting as guards) into unconditional arithmetic, bitwise, or min/max operations. This pattern is poorly handled because the original `select` often acts as a crucial guard against poison-generating instructions, out-of-bounds shifts, or UB-inducing operands. When the guard is removed or folded, the pass frequently fails to drop the associated poison-generating flags or FMFs. Consequently, `poison` or Undefined Behavior that was safely bypassed in the original code propagates unconditionally in the optimized code.

### Pattern 2: Demanded Bits and Elements Simplification
Optimizations often simplify operands based on the subset of bits or vector lanes demanded by their users. This pattern causes issues because the pass fails to strip poison-generating return attributes (like `range` metadata) after altering the underlying value's non-demanded bits. In vector operations, replacing undemanded lanes with `poison` can corrupt subsequent deduplication or `select` folding if those lanes are later demanded. Furthermore, simplifying a multi-use instruction based on the demanded bits of only a single user corrupts the value for all other users.

### Pattern 3: Speculation and Hoisting of Non-Speculatable Instructions
The compiler attempts to hoist instructions (such as division, remainder, or memory accesses) above control flow, or distributes them over `select` instructions to enable further folding. This is not well handled because hoisting non-speculatable instructions into a less-restricted context can introduce immediate Undefined Behavior. If the pass substitutes operands with constants (e.g., replacing a variable with `0` or `null` based on a condition) while the instruction is executed speculatively, it triggers traps like division-by-zero or null-pointer dereferences that were dynamically unreachable in the original program.

### Pattern 4: Pointer Arithmetic (GEP) Reassociation and PHI Folding
To canonicalize memory accesses, the pass merges consecutive `getelementptr` (GEP) instructions, reassociates them, or folds identical GEPs into PHI nodes. This pattern is problematic because the pass often incorrectly retains or improperly intersects the `inbounds` or `nusw` flags during the transformation. When merging GEPs with mixed-sign offsets or folding them through PHI nodes without strict intersection, the pass violates the requirement that all intermediate pointer calculations remain within object bounds, thereby generating `poison`.

### Pattern 5: Fast-Math Flag (FMF) Propagation in Instruction Combining
When commuting, nesting, or folding floating-point operations (e.g., folding a unary operation into a binary operation, or a `select` into a binary operation), the pass transfers FMFs to the newly created instructions. This pattern is poorly handled because the pass frequently copies FMFs unconditionally from an inner or conditionally executed instruction to an outer or unconditional one. This invalidly applies restrictive flags (like `ninf` or `nnan`) to a broader execution context where those assumptions do not hold, causing valid special values to evaluate to `poison`.

### Pattern 6: Instruction Reuse and In-Place State Mutation
To minimize IR size and compile time, the pass reuses existing instructions or mutates them in place when applying transformations like De Morgan's laws, algebraic simplifications, or PHI node folding. This causes miscompilations because reusing instructions without stripping their context-specific poison-generating flags (`nsw`, `nuw`, `disjoint`) makes the new context overly restrictive. Additionally, in-place mutation of interdependent operands (e.g., sinking a `not` into logical operations) or accepting instructions defined later in the basic block during PHI folding can lead to operating on stale states or breaking SSA dominance.
