# Subsystem Knowledge for DeadStoreElimination
## Elements Frequently Missed

*   **Pointer Attributes on Modified Pointers**: Attributes such as `dereferenceable`, `dereferenceable_or_null`, and `align` are frequently missed or incorrectly preserved when DSE modifies or offsets a base pointer (e.g., when shortening a memory intrinsic). The pass fails to drop or recalculate these attributes for the new pointer, leading to over-promised memory bounds or alignment violations.
*   **Attribute Interactions and Semantics (`byval` vs. `initializes`)**: The pass misses the overriding semantics of the `byval` attribute when it appears alongside `initializes`. DSE fails to account for the fact that `byval` creates a private local copy for the callee, meaning the `initializes` attribute only applies to the copy, not the caller's original memory.
*   **Loop Context and Allocation Scope**: The basic block location and loop-variance of memory allocation instructions (like `malloc`) are missed. DSE merely checks if a base pointer originates from an allocation instruction without verifying if the allocation resides outside the loop (e.g., in the entry block), leading to incorrect assumptions about memory invariance across loop iterations.
*   **Ephemeral Values in Pointer Capture Tracking**: Uses of pointers in "ephemeral" instructions (instructions whose results are only used by assumption intrinsics like `llvm.assume`) are prematurely missed or ignored during escape analysis. DSE relies on this flawed analysis, missing the fact that the pointer has technically escaped as long as the ephemeral instruction remains in the IR.

## Patterns Not Well Handled

### Pattern 1: Memory Intrinsic Shortening with Stale Pointer Attributes
When DSE detects that the prefix of a memory intrinsic (like `llvm.memset` or `llvm.memcpy`) is overwritten by subsequent stores, it optimizes the intrinsic by advancing its base pointer and reducing its length. However, this pattern is not well handled because DSE blindly copies the original pointer's attributes (such as `dereferenceable(N)`) to the newly offset pointer. Because the pointer has advanced, the original dereferenceable bytes or alignment guarantees are no longer valid, causing the compiler to introduce undefined behavior by over-promising safe memory bounds on the shortened intrinsic.

### Pattern 2: Cross-Procedural Attribute Misinterpretation
This pattern involves a caller storing a value to memory and passing that memory's pointer to a callee, where the callee's parameter is marked with both `byval` and `initializes`. DSE handles this combination poorly because it misinterprets the scope of the `initializes` attribute. It assumes the callee will overwrite the caller's original memory and erroneously flags the caller's preceding store as dead. It fails to recognize that `byval` restricts the initialization strictly to the callee's private copy, resulting in the caller's memory being left uninitialized or holding stale values.

### Pattern 3: Loop-Variant Allocation Aliasing
When a memory allocation instruction is located inside a loop, followed by an in-loop store and a post-loop store, DSE incorrectly handles the aliasing of the allocated memory. The pass assumes that because the base pointer comes from an allocation, it refers to the exact same memory location across all iterations. By failing to verify that the allocation is loop-invariant, DSE wrongly concludes that the single post-loop store (which only affects the final iteration's allocation) completely overwrites the in-loop stores for *every* iteration. Consequently, it aggressively and incorrectly eliminates the in-loop stores as dead.

### Pattern 4: Premature Discarding of Ephemeral Uses in Escape Analysis
DSE relies heavily on pointer capture tracking to determine if memory is strictly local. A pattern that is poorly handled occurs when a pointer is captured by an "ephemeral" instruction (tied to `llvm.assume`). The underlying analysis prematurely ignores these ephemeral values, falsely reporting to DSE that the pointer does not escape. DSE then aggressively eliminates stores to that memory, assuming they are dead. However, because the ephemeral instructions (or related operations) still exist in the IR at this stage, they can still execute and access the memory, leading to the program reading uninitialized or stale data due to the incorrectly removed stores.
