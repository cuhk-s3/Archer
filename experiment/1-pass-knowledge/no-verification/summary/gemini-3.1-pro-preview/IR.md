# Subsystem Knowledge for IR
## Elements Frequently Missed

*   **1-Bit Integer Semantics and Boundaries**: The unique mathematical properties of 1-bit integers (`i1`) are frequently overlooked. Optimizations often apply general integer rules, missing that the signed range is strictly `[-1, 0]`, the bit pattern for `1` represents `-1`, and operations like adding one to the maximum absolute value will immediately wrap around.
*   **Poison-Generating Flags**: Flags that conditionally generate poison (such as `samesign` on compares) are often missed during control flow simplification. Optimizers treat the instructions as universally safe to hoist or evaluate unconditionally, ignoring that violating the flag's semantic conditions produces poison.
*   **UB-Implying Attributes**: Attributes like `noundef`, `dereferenceable`, or `dereferenceable_or_null` on function calls are frequently ignored during safety checks for speculative execution. The analysis misses that these attributes can escalate otherwise benign speculative values (like `undef` or `poison`) into immediate undefined behavior.
*   **Volatile Qualifiers on Memory Operations**: The implicit side effects dictated by the `volatile` keyword are often missed by interprocedural memory effect analyses. Optimizers focus only on the explicit pointer arguments (e.g., local allocas or constants) and miss that `volatile` operations can interact with inaccessible memory or observable state.
*   **Internal Representations of Same-Width Types**: The distinct internal binary representations of floating-point types with the same bit width (e.g., `bfloat` vs. `half`) are missed during cast elimination. Optimizers incorrectly assume that identical bit widths imply semantic equivalence.
*   **Scalar vs. Vector Pointer Distinctions**: The structural difference between scalar pointers and vectors of pointers (e.g., `<1 x ptr>`) is missed during pointer stripping logic. Analyses fail to halt when encountering non-scalar pointers, feeding invalid types to downstream passes like Alias Analysis.

## Patterns Not Well Handled

### Pattern 1: Speculative Execution and Hoisting Ignoring Poison/UB Constraints
The optimization pass struggles with safely hoisting or speculatively evaluating instructions that carry poison-generating flags or UB-implying attributes. When an instruction is moved out of a conditional context (like a `select` or branch) or evaluated speculatively with edge-specific constraints, the optimizer fails to strip these restrictive flags and attributes. Consequently, conditions that would have dynamically protected the program from undefined behavior or poison are bypassed, causing the compiler's internal analysis to deduce false constraints or introduce unconditional miscompilations.

### Pattern 2: Eager Folding Over Conditional Constructs
The optimizer does not well handle threading operations (such as vector division or remainder) over conditional instructions like `select` when one of the potential operands contains a UB-inducing value (e.g., `0` or `undef`). The simplification logic eagerly evaluates the operation against all possible constant arms independently. If it encounters a division by zero, it folds the entire operation for that arm into `poison`. This pattern fails to account for the fact that the `select` condition might dynamically mask the invalid operand, leading to the unwarranted propagation of `poison` into the final result.

### Pattern 3: Over-Aggressive Cast Elimination and Pointer Stripping
Transformations that attempt to look through or eliminate cast instructions (like `bitcast`) frequently mishandle type semantics. The optimizer relies on superficial checks—such as matching bit widths for floating-point types or blindly traversing cast chains to find underlying objects—without verifying strict semantic compatibility. This leads to the illegal removal of necessary conversions (altering numerical values) or the leaking of unsupported types (like vector pointers) into analyses that strictly require scalar pointers, ultimately corrupting alias analysis and constant folding.

### Pattern 4: Applying General Integer Arithmetic Rules to 1-Bit Arithmetic
The optimization pass fails to handle the extreme edge cases of 1-bit arithmetic during range analysis and overflow inference. By applying generalized integer logic to `i1` types, the compiler incorrectly assumes that operations like multiplying by `1` cannot overflow, or that adding `1` to a maximum absolute value yields a valid upper bound. Because `i1` arithmetic wraps around almost immediately, these flawed assumptions result in the incorrect attachment of `nsw` (no signed wrap) flags or the generation of empty constant ranges, leading to aggressive and invalid constant folding.

### Pattern 5: Over-Constraining Memory Effects by Ignoring Implicit Semantics
Interprocedural analysis patterns that infer function-level memory attributes (like `memory(none)`) do not well handle intrinsics with implicit side effects, such as `volatile` memory operations. The analysis pattern is overly reliant on examining explicit memory operands. When it sees that a volatile intrinsic only touches local or constant memory, it incorrectly deduces that the function has no observable side effects. This flawed deduction allows subsequent passes to illegally delete, reorder, or hoist calls to the function, breaking the strict execution guarantees required by `volatile` semantics.
