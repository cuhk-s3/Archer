## Test Strategies

### Strategy 1: Test with same-sign infinities without ninf/nnan flags

- **Target**: fcmp_oeq_fsub_const and similar tests
- **Rationale**: The fix checks for inf-inf=nan case for predicates UGT, ULT, UNE, OEQ, OGE, OLE. When x=+inf and y=+inf, x-y=nan. For OEQ, fcmp oeq nan 0 returns false, but fcmp oeq +inf +inf returns true. This is a semantic difference. The fix should NOT transform this case unless ninf or nnan flag is set, or one operand is known non-infinity.
- **Expected Issue**: Miscompilation: fcmp oeq (inf - inf), 0 should return false (nan comparison), but transformed fcmp oeq inf, inf returns true

### Strategy 2: Test with non-IEEE denormal mode

- **Target**: fcmp_ogt_fsub_const_vec_denormal_* tests
- **Rationale**: The fix only applies when denormal mode is IEEE. Tests with 'positive-zero', 'preserve-sign', or 'dynamic' denormal modes should NOT be transformed. Need to verify the transformation is correctly blocked for these cases.
- **Expected Issue**: Miscompilation: When denormal mode is not IEEE, the transformation fcmp pred (x-y), 0 -> fcmp pred x, y may produce different results for subnormal values

### Strategy 3: Test FMF propagation on fcmp after transformation

- **Target**: Tests with fcmp having fast-math flags
- **Rationale**: When the fcmp has fast-math flags like nnan or ninf, these flags apply to the comparison operands. After transformation, the flags remain but now apply to x and y instead of (x-y) and 0. This could change semantics if x or y can be NaN/inf but (x-y) cannot.
- **Expected Issue**: Incorrect FMF semantics: fcmp nnan oeq (x-y), 0 transformed to fcmp nnan oeq x, y - the nnan flag now incorrectly assumes x and y are not NaN

### Strategy 4: Test vector types with partial infinity knowledge

- **Target**: Vector fcmp tests with ninf/ninf flags
- **Rationale**: For vector types, isKnownNeverInfinity returns true only if ALL elements are known non-infinity. If only some lanes are known, the transformation might be incorrectly applied or blocked. Need to test cases where vector elements have mixed infinity knowledge.
- **Expected Issue**: Vector lane corruption: Some lanes might be incorrectly transformed when only partial infinity knowledge is available

### Strategy 5: Test predicates UGT, ULT, UNE with inf-inf case

- **Target**: fcmp_ugt_fsub_const, fcmp_ult_fsub_const, fcmp_une_fsub_const
- **Rationale**: For UGT/ULT/UNE predicates, when x=y=inf, x-y=nan. fcmp ugt nan 0 returns true (unordered), but fcmp ugt inf inf returns false (inf is not > inf, and neither is NaN). The fix has a check for this case, but it falls through to the general case. Need to verify the logic is correct.
- **Expected Issue**: Miscompilation: fcmp ugt (inf - inf), 0 returns true, but fcmp ugt inf, inf returns false - semantic mismatch
