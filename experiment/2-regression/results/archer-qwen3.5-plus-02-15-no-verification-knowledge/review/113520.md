## Test Strategies

### Strategy 1: Test truncation when MinBWs entry is missing

- **Target**: vectorizeTree cast handling for alternate nodes
- **Rationale**: The fix at line 12610 uses It->second.first without checking if It is valid in the new conditional block. When BWSz <= SrcBWSz but It == MinBWs.end(), the code will crash or use invalid data.
- **Expected Issue**: Assertion failure or crash when accessing It->second.first when It == MinBWs.end()

### Strategy 2: Test sign extension vs zero extension mismatch

- **Target**: Cast opcode selection in alternate node vectorization
- **Rationale**: The fix compares bitwidths but doesn't properly handle the case where sign extension is needed vs zero extension. When BWSz > SrcBWSz and the signedness information is not properly propagated, wrong cast type may be generated.
- **Expected Issue**: Incorrect sign extension (sext vs zext) leading to wrong numerical results for negative values

### Strategy 3: Test cost/codegen mismatch for alternate casts

- **Target**: getEntryCost vs vectorizeTree consistency
- **Rationale**: The cost calculation uses SrcIt and It differently to determine cast type, but the codegen path only uses It. This can lead to a mismatch where the cost model predicts one cast type but the codegen generates another.
- **Expected Issue**: SLPVectorizer makes wrong vectorization decisions due to cost/model mismatch, either missing profitable vectorization or performing unprofitable vectorization

### Strategy 4: Test mixed bitwidth alternate operations

- **Target**: Alternate node handling with different source operand bitwidths
- **Rationale**: When main and alternate operands have different source bitwidths (e.g., one from MinBWs with reduced bitwidth, one without), the unified SrcTy approach may incorrectly compute costs or generate wrong casts.
- **Expected Issue**: Incorrect vectorization cost calculation or wrong cast instruction generated, leading to semantic changes

### Strategy 5: Test floating-point to integer cast with MinBWs

- **Target**: Cast operations involving floating-point types
- **Rationale**: The fix adds a check for isIntegerTy() but the original code path for floating-point casts may interact incorrectly with MinBWs analysis. Testing FPToUI/FPToSI with alternate nodes can expose issues.
- **Expected Issue**: Incorrect handling of floating-point conversions when MinBWs analysis is involved, potentially causing wrong cast opcodes or crashes
