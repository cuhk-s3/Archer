## Test Strategies

### Strategy 1: Non-commutative ICMP predicate with swapped operands

- **Target**: foldShuffleOfBinops with icmp slt/sgt/ult/ugt
- **Rationale**: The fix uses IsCommutative to decide whether to swap operands, but for non-commutative predicates like slt, sgt, ult, ugt, the code at line 1668-1669 may incorrectly swap operands without changing the predicate. For example, if LHS is 'icmp slt A, B' and RHS is 'icmp slt B, A', the swap would produce incorrect results because slt is not commutative.
- **Expected Issue**: The transformation would produce 'icmp slt shuffle(A,B), shuffle(B,A)' which has different semantics than the original. For slt, A<B is not equivalent to B<A.

### Strategy 2: Non-commutative FCmp predicate with swapped operands

- **Target**: foldShuffleOfBinops with fcmp olt/ogt/ule/uge
- **Rationale**: Similar to ICMP, FCmp predicates like olt, ogt, ole, oge are not commutative. The fix only checks isCommutative() which returns false for these predicates, but the test should verify that the transformation doesn't incorrectly apply when operands have different ordering.
- **Expected Issue**: Incorrect transformation of fcmp with ordered comparison predicates where operand order matters.

### Strategy 3: FCmp fast-math flags not preserved

- **Target**: foldShuffleOfBinops with fcmp having fast-math flags
- **Rationale**: When creating the new fcmp instruction at line 1724 using Builder.CreateCmp(), the fast-math flags from the original fcmp instructions are not explicitly preserved. The original fcmp might have nnan, ninf, or other flags that affect semantics.
- **Expected Issue**: The transformed fcmp loses fast-math flags, potentially changing the semantics (e.g., NaN handling behavior).

### Strategy 4: ICMP/FCmp with poison in shuffle mask

- **Target**: foldShuffleOfBinops with icmp/fcmp and poison mask elements
- **Rationale**: The original code has a check at line 1650-1651 to prevent introducing poison into div/rem operations. However, there's no similar protection for compare operations. While compares don't cause UB, the transformation might still be incorrect if poison elements affect the result differently.
- **Expected Issue**: The transformation might incorrectly proceed when the shuffle mask contains poison elements, potentially changing the observable behavior.

### Strategy 5: Mixed ICMP and FCmp predicate types

- **Target**: foldShuffleOfBinops ensuring predicate consistency
- **Rationale**: The m_Cmp matcher matches both ICmpInst and FCmpInst. The code checks that LHS->getOpcode() == RHS->getOpcode() at line 1640, which should prevent mixing icmp and fcmp. However, the test should verify that the predicate type (ICmp vs FCmp) is correctly handled and that predicates are compatible.
- **Expected Issue**: Potential issues when the predicate matching doesn't correctly distinguish between ICMP and FCmp predicates, or when predicate values are incompatible.
