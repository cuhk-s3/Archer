## Test Strategies

### Strategy 1: Test signed predicate with boundary constant

- **Target**: foldICmpShlConstant with signed predicates (slt, sgt, sle, sge)
- **Rationale**: The getFlippedStrictnessPredicateAndConstant function uses isSigned(Pred) to check for overflow, but WillIncrement is based on unsigned predicate. For signed predicates near INT_MIN/INT_MAX, the overflow check might be incorrect, potentially allowing invalid transformations or blocking valid ones.
- **Expected Issue**: Either a missed optimization opportunity or an incorrect transformation that changes semantics when the constant is at signed boundary values

### Strategy 2: Test vector types with undef/poison elements

- **Target**: foldICmpShlConstant with vector types containing undef or poison elements
- **Rationale**: The getFlippedStrictnessPredicateAndConstant function has special handling for vectors with undef elements (replacing them with a safe constant). However, the interaction between this replacement and the subsequent truncation with nsw flag could produce unexpected poison propagation.
- **Expected Issue**: Incorrect poison propagation or missed optimization when vector elements contain undef values

### Strategy 3: Test nsw flag preservation with truncation

- **Target**: foldICmpShlConstant where the shl has nsw flag and truncation would truncate non-sign bits
- **Rationale**: The code passes Shl->hasNoSignedWrap() to CreateTrunc. However, if the truncation removes bits that don't match the sign bit of the truncated result, the nsw flag on trunc could incorrectly produce poison. The original shl's nsw flag doesn't guarantee the trunc's nsw condition is satisfied.
- **Expected Issue**: Incorrect poison generation when truncating values where the truncated bits don't match the result's sign bit

### Strategy 4: Test flipped constant still failing countr_zero check

- **Target**: Cases where getFlippedStrictnessPredicateAndConstant succeeds but the flipped constant still has countr_zero() < Amt
- **Rationale**: After flipping strictness and adjusting the constant, the code checks RHSC.countr_zero() >= Amt. But if the flipped constant also doesn't have enough trailing zeros, the transformation won't happen. This is a missed optimization case that should be tested to ensure no incorrect transformation occurs.
- **Expected Issue**: Missed optimization opportunity - the code should not apply an incorrect transformation when the flipped constant still doesn't satisfy the trailing zeros requirement

### Strategy 5: Test with constant that becomes min/max after flip

- **Target**: foldICmpShlConstant where flipping strictness would make the constant overflow/underflow
- **Rationale**: The getFlippedStrictnessPredicateAndConstant function checks if the constant can be safely incremented/decremented. For constants at boundary (0 for ult/slt, max for ugt/sgt), the flip should be rejected. Test to ensure the function correctly returns std::nullopt and no incorrect transformation occurs.
- **Expected Issue**: Either incorrect transformation when constant is at boundary, or the function correctly returns std::nullopt and the original comparison is preserved

### Analysis

### Bug Triggering Analysis
The fix extends `foldICmpShlConstant` to handle cases where the comparison constant doesn't have enough trailing zeros by flipping the predicate strictness. After extensive testing with various edge cases including:
- Signed predicate boundary cases (slt/slt with INT_MIN/INT_MAX)
- Unsigned predicate boundary cases (ult/ugt with 0 and UINT_MAX)
- Vector types
- NSW/NUW flag propagation
- Multi-use scenarios
- Constants that would overflow/underflow after flip

All transformations were verified correct by Alive2. The fix correctly:
1. Only applies the flipped strictness transformation when the predicate is strict (ult, ugt, slt, sgt)
2. Properly checks for overflow/underflow before incrementing/decrementing the constant
3. Correctly handles the case where the flipped constant still doesn't have enough trailing zeros (transformation is not applied)
4. Properly propagates the nsw flag from shl to trunc

### Fix Weakness Analysis
The fix appears to be correct and complete. The key insight is that `getFlippedStrictnessPredicateAndConstant` already has robust overflow checking using `isMaxValue(IsSigned)` and `isMinValue(IsSigned)` which correctly handles both signed and unsigned predicates. The transformation only proceeds when:
1. The original constant has insufficient trailing zeros
2. The predicate is strict (relational, not equality)
3. The flipped constant can be safely computed (no overflow)
4. The flipped constant has sufficient trailing zeros

No bugs were found in the tested scenarios. The fix correctly addresses the regression mentioned in the commit message.
