## Test Strategies

### Strategy 1: ScalableVectorEarlyExitInterleave

- **Target**: Test ExtractLane with scalable vectors and interleaving
- **Rationale**: The ExtractLane implementation uses RuntimeVF for scalable vectors. The select chain logic may not correctly handle cases where the runtime vector length varies, potentially causing incorrect lane extraction when VF is scalable and UF > 1.
- **Expected Issue**: Incorrect value extracted from wrong lane or part, leading to wrong early-exit value and miscompilation

### Strategy 2: AllLanesInactiveEarlyExit

- **Target**: Test early exit when all lanes in a vector are inactive (mask is all false)
- **Rationale**: FirstActiveLane returns VF when all lanes are inactive. If this value is used as LaneToExtract, it could be out of bounds for the last part, causing poison propagation or incorrect extraction.
- **Expected Issue**: Poison value propagated to exit block, causing undefined behavior or crash

### Strategy 3: MultiPartNonUniformActiveLanes

- **Target**: Test interleaved early exit where different parts have different active lane patterns
- **Rationale**: The FirstActiveLane computation and ExtractLane select chain assume consistent behavior across parts. Non-uniform active lane patterns across parts could cause the wrong part's value to be selected.
- **Expected Issue**: Wrong value extracted from incorrect part, leading to incorrect loop exit value

### Strategy 4: ExtractLaneUnrollEdgeCases

- **Target**: Test ExtractLane with UF=1 and UF=2 during unrolling
- **Rationale**: The unroll handling adds operands for parts 1 to UF-1. Edge cases like UF=1 (no additional operands) or large UF values need verification to ensure the operand list is correctly constructed.
- **Expected Issue**: Missing operands for parts during unrolling, causing incorrect extraction or assertion failure

### Strategy 5: LaneIndexBoundaryConditions

- **Target**: Test ExtractLane with lane indices at boundaries (0, VF-1, VF, VF*UF-1)
- **Rationale**: Boundary conditions in the select chain logic (ICmpUGE comparisons) could have off-by-one errors. Testing exact boundary values can expose incorrect comparison logic.
- **Expected Issue**: Off-by-one error in select condition causes extraction from wrong part or index

### Analysis

### Bug Triggering Analysis
The test cases verify the ExtractLane VPInstruction implementation for early-exit loops with interleaving. The patch adds ExtractLane to handle extraction across multiple parts using a wide index, replacing ExtractElement which only works per-part.

The test cases cover:
1. **LaneIndexBoundaryConditions**: Tests early exit at lane 0 (first lane of first part) with VF=4, UF=2. The ExtractLane should correctly extract from part 0, lane 0.
2. **ExtractLaneUnrollEdgeCases**: Tests with UF=4 to verify unroll handling with multiple parts (4 parts with 16 total lanes).
3. **AllLanesInactiveEarlyExit**: Tests when all lanes are equal (no early exit trigger), FirstActiveLane should return VF.
4. **MultiPartNonUniformActiveLanes**: Tests interleaved early exit where different parts have different active lane patterns.
5. **ScalableVectorEarlyExitInterleave**: Tests early exit with scalable vectors and interleaving.

All test cases passed differential testing (no differences found between original and transformed code), indicating the ExtractLane implementation is working correctly for these scenarios.

### Fix Weakness Analysis
The fix correctly implements ExtractLane to:
1. Handle multiple vector operands (parts) with a wide lane index
2. Use RuntimeVF for scalable vectors
3. Properly handle unrolling by adding operands for each part
4. Correctly compute the select chain to pick the right value from the right part

The tests verify that:
- Lane index 0 correctly extracts from part 0, lane 0
- Lane index VF correctly extracts from part 1, lane 0
- The select chain logic (ICmpUGE comparisons) works correctly at boundaries
- Unrolling with UF > 1 correctly adds operands for all parts
- Scalable vector handling with RuntimeVF works correctly

No bugs were found in the tested scenarios. The fix appears to be correct for the tested edge cases.
