## Test Strategies

### Strategy 1: Test nusw-only GEP comparison with unsigned predicate

- **Target**: foldGEPICmp with GEPs having only nusw flag (no nuw)
- **Rationale**: The patch converts unsigned icmp to signed icmp when GEPs have nusw but not nuw. This conversion assumes the semantics are equivalent, but there may be edge cases where the unsigned comparison of pointers differs from signed comparison of offsets when offsets can be negative.
- **Expected Issue**: Miscompilation when comparing GEPs with nusw-only flags where the offset signs cause different results between unsigned pointer comparison and signed offset comparison

### Strategy 2: Test mixed nowrap flags on LHS and RHS GEPs

- **Target**: foldGEPICmp where LHS has nuw and RHS has nusw (or vice versa)
- **Rationale**: The code intersects flags from both GEPs (line 807). If LHS has nuw-only and RHS has nusw-only, the intersection is empty, preventing folding. But if one GEP has inbounds (implying nusw) and the other has nuw-only, the intersection is nuw, which may not correctly capture the semantics of both GEPs.
- **Expected Issue**: Incorrect folding or missed optimization when GEPs have asymmetric nowrap flags, potentially leading to wrong predicate selection or missing samesign flag

### Strategy 3: Test samesign flag with offsets of different signs

- **Target**: foldGEPICmp with nusw+nuw GEPs where computed offsets have opposite signs
- **Rationale**: The patch sets samesign flag when nusw is present along with nuw. However, if the offsets can legitimately have different signs while the GEPs still satisfy nusw+nuw constraints, the samesign flag would incorrectly produce poison.
- **Expected Issue**: Poison propagation when offsets have different signs but the original pointer comparison was well-defined, causing incorrect undefined behavior

### Strategy 4: Test GEP vs base pointer comparison with nuw-only

- **Target**: foldGEPICmp case where RHS is the base pointer (line 713-718) with nuw-only GEP
- **Rationale**: The code path at line 713-718 handles (gep Ptr, OFFSET) cmp Ptr. With nuw-only, NewICmp uses unsigned predicate. Need to verify this is correct when offset could be negative (which nuw alone doesn't prevent).
- **Expected Issue**: Incorrect comparison result when GEP has nuw-only and negative offset, as unsigned comparison of offset vs 0 may not match unsigned comparison of (ptr+offset) vs ptr

### Strategy 5: Test vector GEP comparisons with mixed nowrap flags per lane

- **Target**: foldGEPICmp with vector GEPs where different lanes have different effective nowrap behavior
- **Rationale**: Vector GEPs apply flags to all lanes. If some lanes would violate nusw/nuw constraints while others don't, the intersection of flags might not correctly represent the per-lane semantics, leading to incorrect samesign or predicate selection.
- **Expected Issue**: Miscompilation in vector cases where per-lane nowrap guarantees differ, causing incorrect poison propagation or wrong comparison results in some lanes
