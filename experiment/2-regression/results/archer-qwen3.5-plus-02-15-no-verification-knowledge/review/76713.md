## Test Strategies

### Strategy 1: Pointer argument type handling

- **Target**: Function with pointer-type arguments
- **Rationale**: The fix unconditionally adds Var >= 0 constraints for all function arguments in the constructor (lines 277-284) without checking if the argument is an integer type. Pointer types should not have non-negativity constraints added as they are not ordered in the same way as integers.
- **Expected Issue**: The constraint system may incorrectly reason about pointer values, potentially leading to incorrect optimizations or assertion failures when the constraint solver tries to process pointer-typed variables with integer constraints.

### Strategy 2: Vector argument type handling

- **Target**: Function with vector-type arguments
- **Rationale**: Similar to pointers, the fix does not check if function arguments are vector types before adding Var >= 0 constraints. Vector types are handled differently in decompose (line 479 uses getScalarType) and should not have simple non-negativity constraints.
- **Expected Issue**: The constraint system may crash or produce incorrect results when trying to apply scalar integer constraints to vector-typed variables.

### Strategy 3: New variables from signed constraints used in unsigned context

- **Target**: Test case where a variable is first introduced via a signed constraint, then used in an unsigned constraint
- **Rationale**: The fix only adds Var >= 0 constraints for new variables when !R.IsSigned (line 1478). If a variable is first introduced in a signed constraint context, it won't get a Var >= 0 constraint. When later used in an unsigned context, the variable may already be in SignedCS.getValue2Index() but not UnsignedCS.getValue2Index(), potentially causing inconsistent handling.
- **Expected Issue**: Missing Var >= 0 constraint for variables that cross from signed to unsigned contexts, leading to missed optimizations or incorrect constraint propagation.

### Strategy 4: New variables with zero coefficients after decomposition

- **Target**: Test case where decomposition results in new variables that are later eliminated due to zero coefficients
- **Rationale**: The code at lines 689-698 removes new variables with zero coefficients from NewVariables. However, the Var >= 0 constraint addition at lines 1478-1487 iterates over NewVariables after they've been added to Value2Index. If a variable was eliminated due to zero coefficient, it shouldn't get a Var >= 0 constraint.
- **Expected Issue**: Spurious Var >= 0 constraints may be added for variables that were eliminated during decomposition, causing the constraint system to have extra constraints that don't correspond to actual variables.

### Strategy 5: Large number of new variables causing constraint system explosion

- **Target**: Test case with many new variables introduced in a single unsigned constraint
- **Rationale**: The fix adds one Var >= 0 constraint and one StackEntry for each new variable (lines 1478-1487). With many new variables, this could cause the constraint system to grow rapidly, potentially hitting the MaxRows limit (checked at line 1670) or causing performance issues.
- **Expected Issue**: Compile-time performance degradation or premature hitting of MaxRows limit, causing the pass to skip adding useful constraints.
