## Test Strategies

### Strategy 1: Missing AssumptionCache in ComputeNumSignBits

- **Target**: ComputeNumSignBits calls in InstCombineSimplifyDemanded.cpp
- **Rationale**: The patch passes SimplifyQuery to SimplifyDemandedBits but ComputeNumSignBits calls within the function only receive Q.CxtI, missing Q.AC (AssumptionCache). This can lead to incorrect sign bit computation when assumptions about value ranges are available but not utilized.
- **Expected Issue**: Incorrect sign bit count may be computed, leading to missed optimizations or incorrect transformations that assume more sign bits than actually exist.

### Strategy 2: Missing DominatorTree in ComputeNumSignBits

- **Target**: ComputeNumSignBits calls in InstCombineSimplifyDemanded.cpp
- **Rationale**: The ComputeNumSignBits calls pass only Q.CxtI but not Q.DT (DominatorTree). The DominatorTree is essential for determining control flow relationships and validating assumptions across basic blocks. Without it, ComputeNumSignBits may make overly conservative or incorrect assumptions.
- **Expected Issue**: Sign bit analysis may be overly conservative, missing optimization opportunities, or may incorrectly compute sign bits when control flow information is needed.

### Strategy 3: CondContext Not Propagated to ComputeNumSignBits

- **Target**: ComputeNumSignBits calls in InstCombineSimplifyDemanded.cpp
- **Rationale**: The patch enables CondContext to be set in SimplifyQuery for future use, but ComputeNumSignBits calls don't receive the full SimplifyQuery including CC (CondContext). This means context-sensitive sign bit analysis based on conditional predicates won't work correctly.
- **Expected Issue**: Sign bit analysis won't benefit from conditional context information, potentially missing optimizations that depend on knowing the sign bits under specific conditions.

### Strategy 4: Inconsistent Query Propagation Between computeKnownBits and ComputeNumSignBits

- **Target**: Mixed usage of computeKnownBits vs ComputeNumSignBits in InstCombineSimplifyDemanded.cpp
- **Rationale**: The patch correctly passes full SimplifyQuery to computeKnownBits calls, but ComputeNumSignBits calls only receive Q.CxtI. This inconsistency means different analysis functions have different levels of context, potentially leading to inconsistent results.
- **Expected Issue**: Inconsistent analysis results between computeKnownBits and ComputeNumSignBits could lead to incorrect transformations when both analyses are used together.

### Strategy 5: One-Use Chain Context Instruction Retention Issue

- **Target**: SimplifyDemandedUseBits handling of one-use chains
- **Rationale**: The commit message states the patch 'marginally strengthens the analysis by retaining the original context instruction for one-use chains'. However, when Depth != 0 and the instruction has one use, the code still passes the full Q. But for ComputeNumSignBits calls, only Q.CxtI is passed, potentially losing the original context for sign bit analysis in one-use chains.
- **Expected Issue**: Sign bit analysis in one-use chains may use incorrect context instruction, leading to either missed optimizations or incorrect transformations that assume wrong sign bit counts.
