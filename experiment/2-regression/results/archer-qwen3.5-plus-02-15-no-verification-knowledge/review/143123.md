## Test Strategies

### Strategy 1: Test FMF flag mismatch between select and fcmp

- **Target**: Create test where select has different FMF flags than fcmp (e.g., select has nsz but fcmp doesn't, or vice versa)
- **Rationale**: The fix passes FMF from select to matchDecomposedSelectPattern, but only merges nnan from fcmp. If select has nsz but fcmp doesn't (or vice versa), the behavior might differ from before. Need to verify the fix correctly handles cases where FMF flags differ between the two instructions.
- **Expected Issue**: Incorrect min/max pattern matching when FMF flags differ between select and fcmp, potentially leading to wrong fabs/min/max transformations

### Strategy 2: Test fcmp with nnan but select without nnan

- **Target**: Create test where fcmp has nnan flag but select does not have nnan
- **Rationale**: The fix only sets NoNaNs from fcmp if fcmp has nnan. But if select doesn't have nnan, the combined FMF might incorrectly allow transformations that assume no NaN when the select could receive NaN values.
- **Expected Issue**: Incorrect transformation to fabs when fcmp has nnan but select doesn't, potentially changing NaN handling semantics

### Strategy 3: Test select with FMF but fcmp without FMF

- **Target**: Create test where select has FMF flags (nnan, nsz) but fcmp has no FMF flags
- **Rationale**: The fix passes FMF from select, but only adds nnan from fcmp if fcmp has it. If fcmp has no FMF, the analysis might miss important constraints or incorrectly apply select's FMF to the comparison operands.
- **Expected Issue**: Incorrect pattern matching when select has FMF but fcmp doesn't, potentially missing valid optimizations or applying invalid ones

### Strategy 4: Test signed zero handling with nsz flag mismatch

- **Target**: Create test involving -0.0 and +0.0 where select has nsz but fcmp doesn't (or vice versa)
- **Rationale**: The code at line 8626 checks FMF.noSignedZeros() to decide whether to proceed with min/max matching. If FMF comes from select but the signed zero semantics depend on fcmp, there could be a mismatch causing incorrect handling of -0.0 vs +0.0.
- **Expected Issue**: Incorrect sign of zero in result when nsz flag differs between select and fcmp, violating IEEE-754 semantics

### Strategy 5: Test vector types with mixed FMF per lane

- **Target**: Create test with vector fcmp/select where some lanes have different FMF characteristics
- **Rationale**: Vector operations can have per-element semantics. The fix uses isa<FPMathOperator>(SI) to check if select is FP, but vector FMF handling might have edge cases where some elements are poison/undef or have different FP classes.
- **Expected Issue**: Incorrect pattern matching for vector operations with mixed FMF or poison elements, leading to wrong min/max/fabs transformations
