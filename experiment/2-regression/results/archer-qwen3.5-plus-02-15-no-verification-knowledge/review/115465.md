## Test Strategies

### Strategy 1: Vector condition with element permutation

- **Target**: shufflevector(select<vector_condition, x, y>, constant, non_identity_mask)
- **Rationale**: The transformation incorrectly assumes that shufflevector(select(cond, x, y), mask) equals select(cond, shufflevector(x, mask), shufflevector(y, mask)). When cond is a vector (per-lane select) and mask permutes elements, the original uses cond[source_element] while the transformed uses cond[result_element], producing different results.
- **Expected Issue**: Miscompilation: The transformed code produces different values than the original when the select condition is a vector and the shuffle mask permutes elements across lanes.

### Strategy 2: Scalar select condition with permutation (should work)

- **Target**: shufflevector(select<scalar_condition, x, y>, constant, non_identity_mask)
- **Rationale**: When the select condition is a scalar i1, the entire vector is selected uniformly, so the transformation should be valid. This tests the positive case to ensure the fix works correctly for valid inputs.
- **Expected Issue**: Should compile correctly - verifies the transformation works for scalar select conditions.

### Strategy 3: Vector condition with identity mask (should work)

- **Target**: shufflevector(select<vector_condition, x, y>, constant, identity_mask)
- **Rationale**: When the shuffle mask is identity (no permutation), the transformation should be valid even with vector conditions because source and result element indices are the same.
- **Expected Issue**: Should compile correctly - verifies the transformation works for identity masks.

### Strategy 4: PHI node with vector shuffle permutation

- **Target**: shufflevector(phi(x, y), constant, non_identity_mask)
- **Rationale**: Similar to the select case, if the PHI node's incoming values have per-element semantics and the shuffle permutes elements, folding the shuffle into the PHI may produce incorrect results. The foldOpIntoPhi function creates new shufflevectors in predecessor blocks, but the semantics may differ if the PHI represents control-flow-dependent values.
- **Expected Issue**: Potential miscompilation if the PHI represents values from different control flow paths where element-wise semantics matter.

### Strategy 5: Select with poison/undef in arms and non-identity mask

- **Target**: shufflevector(select(cond, x_with_poison, y), constant, permuting_mask)
- **Rationale**: Tests poison propagation through the transformation. If the select arm contains poison and the mask selects from that element, the result should be poison. The transformation must preserve poison semantics correctly.
- **Expected Issue**: Incorrect poison propagation if the transformation doesn't properly handle poison values in select arms with permuting masks.
