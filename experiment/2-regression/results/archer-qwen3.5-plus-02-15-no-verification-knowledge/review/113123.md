## Test Strategies

### Strategy 1: NaN_Value_Test

- **Target**: Test with NaN input values for both ordered and unordered predicates
- **Rationale**: The transformation uses fabs which preserves NaN payloads, but the original fcmp comparisons have different NaN semantics. Need to verify that NaN handling is equivalent between original and transformed code for all predicate combinations (olt/ogt, ole/oge, ult/ugt, ule/uge).
- **Expected Issue**: If NaN handling differs, the transformed code may return different boolean results for NaN inputs, causing miscompilation.

### Strategy 2: Signed_Zero_Test

- **Target**: Test with +0.0 and -0.0 input values
- **Rationale**: IEEE-754 has distinct +0 and -0 representations. The fabs operation normalizes both to +0. Need to verify that the range check semantics are preserved for signed zero inputs, especially when C is small positive values.
- **Expected Issue**: If signed zero handling differs, comparisons involving -0 may produce different results after transformation.

### Strategy 3: Negative_Constant_Test

- **Target**: Test with negative constant C values
- **Rationale**: When C is negative, the range (-C, C) is mathematically empty since -C > C. The transformation should still be semantically correct (always returning false for AND case). This tests edge case handling in the constant negation logic.
- **Expected Issue**: If negative constant handling is incorrect, the transformation may produce wrong results for empty range checks.

### Strategy 4: FMF_Propagation_Test

- **Target**: Test with different Fast Math Flag combinations on the two fcmp instructions
- **Rationale**: The patch unions FMF from both fcmps. Need to verify that this is semantically correct, especially when one fcmp has restrictive flags (nnan, ninf) and the other doesn't. The union might be overly optimistic in some cases.
- **Expected Issue**: If FMF union is incorrect, the transformed code may have different poison/UB behavior than the original.

### Strategy 5: OR_Case_Predicate_Test

- **Target**: Test the OR transformation path with various predicate combinations
- **Rationale**: The patch handles both AND and OR cases with different predicate selection logic. The OR case transforms (fcmp ogt/oge/ugt/uge x, C) OR (fcmp olt/ole/ult/ule x, -C) to fabs(x) ogt/oge/ugt/uge C. This path may have different edge cases than the AND case.
- **Expected Issue**: If OR case logic is incorrect, the complement range check may produce wrong results.
