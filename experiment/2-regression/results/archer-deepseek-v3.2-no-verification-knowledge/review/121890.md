## Test Strategies

### Strategy 1: MixedSignOffsetWithNUW

- **Target**: Test GEP with nuw flag and offset values that have mixed sign bits (e.g., INT_MIN)
- **Rationale**: When converting unsigned comparison to signed for nuw-only GEP, signed overflow semantics might differ from unsigned wrap semantics for values with high bit set
- **Expected Issue**: Incorrect comparison result when offset has sign bit set but doesn't cause unsigned wrap

### Strategy 2: NUSWOnlyFlagCombination

- **Target**: Test GEP with nusw flag only (without nuw)
- **Rationale**: The patch checks NW != none() which includes nusw alone, but NewICmp logic might not handle nusw-only correctly (checks hasNoUnsignedWrap())
- **Expected Issue**: Incorrect predicate selection or missing samesign flag for nusw-only GEPs

### Strategy 3: MultiIndexGEPOffsetOverflow

- **Target**: Test multi-index GEPs where intermediate index calculations might overflow
- **Rationale**: EmitGEPOffset computes total offset, but intermediate overflow in multi-index GEP might violate nowrap semantics even if final offset doesn't wrap
- **Expected Issue**: Incorrect folding when intermediate GEP index calculations overflow

### Strategy 4: VectorGEPPerLaneSemantics

- **Target**: Test vector GEPs with nowrap flags and vector offsets
- **Rationale**: Vector GEP nowrap semantics might be per-lane, but transformation might incorrectly apply scalar logic
- **Expected Issue**: Incorrect lane-wise comparison results or missing per-lane samesign flags

### Strategy 5: PoisonOffsetPropagation

- **Target**: Test GEPs with poison/undef offset values
- **Rationale**: Transformation might incorrectly propagate poison or create new poison when converting comparison types
- **Expected Issue**: Incorrect poison propagation or missing poison in result

### Analysis

## Bug Triggering Analysis\n\nThe bug is in the patch's handling of GEPs with `nusw` (no unsigned signed wrap) flag only (without `nuw`). The patch's `NewICmp` lambda checks `hasNoUnsignedWrap()` which returns false for `nusw`-only GEPs, causing it to convert unsigned comparisons to signed comparisons. However, `nusw` only prevents signed overflow, not unsigned wrap. When the offset is negative (e.g., -1), the unsigned comparison `ult` should return false (since pointer with negative offset is less than base in unsigned comparison), but the transformed signed comparison `slt -1, 0` returns true.\n\n## Fix Weakness Analysis\n\nThe patch incorrectly assumes that any nowrap flag (`nuw`, `nusw`, or both) allows folding unsigned comparisons. However:\n1. `nuw` alone: correctly converts to signed comparison because unsigned wrap prevention ensures offset sign determines comparison\n2. `nusw` alone: incorrectly converts to signed comparison because `nusw` only prevents signed overflow, not unsigned wrap\n3. `nusw nuw` both: correctly keeps unsigned comparison with `samesign` flag\n\nThe fix should distinguish between `nuw` and `nusw` flags: only `nuw` (or `nusw nuw`) should allow unsigned-to-signed conversion for comparisons against base pointer.\n\n## Additional Bugs Found\n1. **Multi-index overflow bug**: For `nusw nuw` GEPs with multi-index and large offset (i64::MAX), original triggers UB (poison) but transformed eliminates poison\n2. **NUSW-only comparison bug**: Two `nusw`-only GEPs being compared with negative offsets produce wrong results after transformation
