## Test Strategies

### Strategy 1: Shuffle mask with poison elements

- **Target**: Shuffle mask elements
- **Rationale**: The patch transforms shufflevector(select, constant) to select(shufflevector(x, constant), shufflevector(y, constant)). If the shuffle mask contains poison elements, the transformation may incorrectly propagate poison semantics or drop poison flags.
- **Expected Issue**: Incorrect poison propagation or missing poison flags in the resulting select/shuffle instructions.

### Strategy 2: Select with poison-generating flags

- **Target**: Select instruction flags
- **Rationale**: The select instruction may have poison-generating flags (nsw, nuw, exact) that need to be properly handled when moving the shuffle inside the select. The FoldOpIntoSelect helper may not correctly preserve or drop these flags.
- **Expected Issue**: Poison-generating flags incorrectly propagated to shufflevector instructions or not properly dropped.

### Strategy 3: PHI with multiple incoming values from same block

- **Target**: PHI node incoming values
- **Rationale**: The foldOpIntoPhi function has complex logic for handling phi-translatable operands and critical edges. If a PHI has multiple incoming values from the same block or involves critical edges, the transformation may incorrectly handle phi translation.
- **Expected Issue**: Incorrect phi translation leading to wrong values or dominance violations.

### Strategy 4: Vector type mismatches and scalable vectors

- **Target**: Vector types and sizes
- **Rationale**: The patch checks for constant RHS but doesn't verify that the shuffle mask length matches the vector types. For scalable vectors or length-changing shuffles, the transformation may produce invalid IR.
- **Expected Issue**: Invalid shufflevector instructions with mismatched vector lengths or unsupported scalable vector operations.

### Strategy 5: Fast-math flags on floating-point vectors

- **Target**: Floating-point vector operations
- **Rationale**: If the select or phi involves floating-point vectors with fast-math flags, these flags need to be properly propagated to the new shufflevector instructions. The helpers may not handle FMF correctly.
- **Expected Issue**: Incorrect fast-math flag propagation leading to invalid optimizations or missed optimizations.

### Reproducer

define <2 x float> @foldselect_fmf(i1 %c) {
  %sel = select fast i1 %c, <2 x float> <float 1.0, float 2.0>, <2 x float> <float 3.0, float 4.0>
  %shuf = shufflevector <2 x float> %sel, <2 x float> <float 5.0, float 5.0>, <2 x i32> <i32 1, i32 0>

}

### Analysis

Bug Triggering Analysis: The transformation drops fast-math flags when folding shufflevector(select, constant) to select(shufflevector(x, constant), shufflevector(y, constant)). The original select has 'fast' flag, but the resulting select does not. This is incorrect because fast-math flags allow optimizations that may not be valid without them. The FoldOpIntoSelect helper should preserve fast-math flags from the original select instruction.

Fix Weakness Analysis: The patch uses FoldOpIntoSelect helper which creates a new select instruction but doesn't copy fast-math flags from the original select. The helper should propagate fast-math flags to maintain semantic equivalence. This violates the subsystem knowledge about Fast-Math Flag (FMF) Propagation in Instruction Combining - flags are not properly propagated when folding operations into select.
