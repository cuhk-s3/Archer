## Test Strategies

### Strategy 1: IR Flag Semantics Violation

- **Target**: Test cases with nuw/nsw/exact flags on interchangeable operations
- **Rationale**: The fix converts between operations with different flag semantics (e.g., add nuw -> shl). shl doesn't support nuw/nsw flags, so flag propagation may be incorrect or lost, potentially allowing undefined behavior that was previously guarded.
- **Expected Issue**: Loss of overflow protection or incorrect exactness semantics leading to miscompilation.

### Strategy 2: Bitwidth and Type Edge Cases

- **Target**: Test cases with i1 types, vector constants, or unusual bitwidths
- **Rationale**: The conversion logic assumes integer semantics but i1 has special behavior (e.g., and i1 x, -1 = x). Vector constants and non-power-of-2 types may have unexpected interactions with APInt conversions.
- **Expected Issue**: Incorrect constant conversion or type mismatches during vectorization.

### Strategy 3: Large Constant Overflow

- **Target**: Test cases with shift amounts near bitwidth or large multipliers
- **Rationale**: Converting shl x, 63 to mul x, 2^63 may overflow differently due to wrapping semantics. The APInt conversion may produce incorrect values for edge cases.
- **Expected Issue**: Incorrect constant values or overflow behavior differences between original and converted operations.

### Strategy 4: Alternate Instruction Priority Conflict

- **Target**: Test cases mixing multiple interchangeable patterns with alternate opcodes
- **Rationale**: When VL contains add, sub, and mul operations, the algorithm must choose which opcode to convert to. Suboptimal choices may increase cost or prevent vectorization where better options exist.
- **Expected Issue**: Suboptimal vectorization or missed optimization opportunities.

### Strategy 5: Poison/Undef Constant Handling

- **Target**: Test cases with undef/poison constants in interchangeable operations
- **Rationale**: The fix assumes constants are ConstantInt, but undef/poison constants have different semantics. add x, undef is not equivalent to mul x, 1.
- **Expected Issue**: Incorrect equivalence classification leading to miscompilation.

### Strategy 6: Cost Model Inconsistency

- **Target**: Test cases where interchangeable conversion changes instruction costs significantly
- **Rationale**: Converting mul to shl changes instruction cost and latency. The cost model may not account for these differences, leading to suboptimal vectorization decisions.
- **Expected Issue**: Poor performance due to incorrect cost estimation.

### Strategy 7: Multi-Use Value Transformation

- **Target**: Test cases where values have multiple uses with different opcode requirements
- **Rationale**: When a value is used in multiple interchangeable contexts, converting one use may affect others. External users may depend on specific opcode or constant values.
- **Expected Issue**: Invalid IR due to changed opcodes affecting other uses or incorrect constant propagation.
