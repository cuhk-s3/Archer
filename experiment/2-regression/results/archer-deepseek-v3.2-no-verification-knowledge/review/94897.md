## Test Strategies

### Strategy 1: Constant Overflow/Underflow Edge Cases

- **Target**: Test constants at type boundaries (min/max values) with strict predicates
- **Rationale**: When flipping strictness, constants are incremented/decremented. At type boundaries, this can overflow/underflow, potentially causing incorrect transformations or missed optimizations.
- **Expected Issue**: Incorrect transformation due to overflow/underflow in constant adjustment, or missed optimization when constant adjustment fails.

### Strategy 2: Vector with Undef/Poison Elements

- **Target**: Test vector constants containing undef/poison elements mixed with concrete values
- **Rationale**: The getFlippedStrictnessPredicateAndConstant function has special handling for undef/poison elements. If not handled correctly, vector transformations could be incorrect.
- **Expected Issue**: Incorrect transformation for vectors with undef/poison elements, or assertion failure in debug builds.

### Strategy 3: Signed Comparisons with Negative Constants

- **Target**: Test signed comparisons (slt/sgt) with negative constants and various shift amounts
- **Rationale**: Signed right shift (ashr) of negative constants preserves sign bits. The transformation uses ashr for both signed and unsigned predicates after flipping. Edge cases with negative constants may not be handled correctly.
- **Expected Issue**: Incorrect transformation for signed comparisons with negative constants, especially when flipping strictness.

### Strategy 4: Scalable Vector Types

- **Target**: Test with scalable vector types (vscale x iN)
- **Rationale**: Scalable vectors have different representation and the getFlippedStrictnessPredicateAndConstant function has special handling for them. The transformation may not handle scalable vectors correctly.
- **Expected Issue**: Incorrect transformation or crash when handling scalable vector types.

### Strategy 5: Type Width Edge Cases

- **Target**: Test with very small target types (e.g., i1, i2) after truncation
- **Rationale**: When TypeBits - Amt results in very small types, the transformation may produce incorrect results or violate type legality constraints.
- **Expected Issue**: Incorrect transformation for very small target types, or violation of type legality constraints.
