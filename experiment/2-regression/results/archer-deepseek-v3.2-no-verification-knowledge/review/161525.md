- **Rationale**: The optimization requires IEEE denormal mode, but functions can have different denormal modes (positive-zero, preserve-sign, dynamic). The check might be incomplete or incorrectly applied.
- **Expected Issue**: Incorrect transformation when denormal mode is not IEEE, leading to wrong comparison results for subnormal values.

### Strategy 2: FastMathFlagPropagation

- **Target**: Fast-math flags on fsub and fcmp
- **Rationale**: The optimization propagates flags from fsub to fcmp but might not handle all flag combinations correctly, especially when fsub and fcmp have different flags.

- **Rationale**: The optimization might not correctly handle vector types where some elements have different properties (e.g., some lanes known never infinity, others not).

# Bug Found: Missing Infinity Check for Group 2 Predicates

## Bug Triggering Analysis
The test case `test_ogt_infinity` exposes a bug where the optimization produces incorrect results for infinity operands with Group 2 predicates.

**Original code**: `fcmp ogt (fsub float %x, %y), 0.0`
- When `%x = +inf` and `%y = +inf`: `fsub +inf - +inf = NaN`
- `fcmp ogt NaN, 0.0` = true (unordered or greater)

**Transformed code**: `fcmp ogt %x, %y`
- When `%x = +inf` and `%y = +inf`: `fcmp ogt +inf, +inf` = false

**The bug**: The transformation changes the result from true to false. This is incorrect because `fcmp ogt NaN, 0` evaluates to true (since NaN is unordered, and "unordered or greater" includes unordered), while `fcmp ogt +inf, +inf` is false.

## Fix Weakness Analysis
The weakness in the fix is the predicate grouping logic. The code divides predicates into two groups:
- **Group 1** (FCMP_UGT, FCMP_ULT, FCMP_UNE, FCMP_OEQ, FCMP_OGE, FCMP_OLE): Has infinity check
- **Group 2** (FCMP_OGT, FCMP_OLT, FCMP_ONE, FCMP_UEQ, FCMP_UGE, FCMP_ULE): No infinity check (via `[[fallthrough]]`)

However, Group 2 predicates also need infinity checks because:
1. `infinity - infinity = NaN` produces different comparison results than `infinity cmp infinity`
2. For example: `fcmp ogt NaN, 0` ≠ `fcmp ogt +inf, +inf`
3. The transformation is not semantics-preserving for infinity operands

The fix should apply infinity checks to ALL predicates when the fsub doesn't have `nnan` or `ninf` flags and neither operand is known never infinity.

## Root Cause
The fundamental issue is that the transformation `fcmp pred (x - y), 0` → `fcmp pred x, y` is only valid when `x - y` doesn't produce NaN from infinity subtraction. This condition applies to ALL predicates, not just a subset.
