## Test Strategies

### Strategy 1: Mixed nowrap flags in trunc-trunc comparison

- **Target**: trunc nuw vs trunc nsw combinations
- **Rationale**: The patch assumes that for unsigned/equality comparisons, either both truncs must be nuw or both must be nsw, but doesn't verify they are the same. A mixed pair (one nuw, one nsw) could incorrectly pass the NoWrapFlags check (non-zero) but violate the semantic requirement that both have the same kind of nowrap guarantee.
- **Expected Issue**: Incorrect transformation leading to miscompilation when comparing values with different nowrap semantics.

### Strategy 2: ConstantExpr trunc with nowrap flags

- **Target**: ConstantExpr trunc with nuw/nsw flags
- **Rationale**: The patch uses cast<TruncInst> on Cmp.getOperand(0/1) which will fail for ConstantExpr truncs. ConstantExpr can also have nowrap flags but won't be matched by the pattern matcher or handled by the cast.
- **Expected Issue**: Missed optimization opportunity or crash when comparing ConstantExpr truncs with nowrap flags.

### Strategy 3: Vector trunc with nowrap flags

- **Target**: vector trunc instructions with nuw/nsw
- **Rationale**: The patch doesn't consider vector types. TruncInst::getNoWrapKind() works for vectors, but the pattern matcher m_Trunc matches CastOperator which includes ConstantExpr. Need to ensure vector truncs with nowrap flags are handled correctly.
- **Expected Issue**: Incorrect handling of vector comparisons or missed optimizations for vector truncs.

### Strategy 4: Incorrect YIsSExt determination for swapped operands

- **Target**: trunc nsw + sext with swapped operands
- **Rationale**: YIsSExt is determined by checking if either operand is SExtInst, but when operands are swapped by m_c_ICmp, the logic may incorrectly identify which operand is the sext.
- **Expected Issue**: Wrong signedness flag passed to CreateIntCast, causing incorrect extension (zext instead of sext or vice versa).

### Strategy 5: Missing poison flag preservation

- **Target**: nowrap flags on newly created icmp
- **Rationale**: The transformation creates a new icmp but doesn't preserve any poison-generating flags from the original truncs. If the original truncs had nuw/nsw flags that could generate poison, the new icmp should have appropriate flags or the transformation should ensure poison safety.
- **Expected Issue**: Loss of poison semantics, potentially turning poison into value-dependent behavior.
