## Test Strategies

### Strategy 1: AbsIntrinsicPoisonFlagMismatch

- **Target**: abs intrinsic with poison flag true
- **Rationale**: The fix sets second argument to false when bitwidth is reduced, but doesn't handle cases where original abs had poison flag true. This could change semantics.
- **Expected Issue**: Different poison semantics when bitwidth reduced

### Strategy 2: MinMaxSignBitAnalysisIncomplete

- **Target**: smin/smax with sign bits analysis edge cases
- **Rationale**: The fix uses ComputeNumSignBits for signed min/max but may miss cases where sign bits differ between operands or where truncation changes sign interpretation.
- **Expected Issue**: Incorrect truncation leading to wrong min/max results

### Strategy 3: UminUmaxMaskedValueZeroFalseNegative

- **Target**: umin/umax with high bits not zero but irrelevant
- **Rationale**: MaskedValueIsZero check may be too strict - high bits might not be zero but still not affect min/max result if values are small enough.
- **Expected Issue**: Missed optimization opportunity

### Strategy 4: MixedIntrinsicTypesInTree

- **Target**: Tree with mixed abs/smin/smax/umin/umax intrinsics
- **Rationale**: The fix handles each intrinsic separately but may not handle trees mixing different intrinsics with different bitwidth requirements.
- **Expected Issue**: Inconsistent bitwidth reduction across tree

### Strategy 5: CostModelVsSemanticsMismatch

- **Target**: Cases where cost model chooses bitwidth that violates semantic checks
- **Rationale**: The fix chooses bitwidth based on cost, but semantic checks (MaskedValueIsZero/ComputeNumSignBits) might pass for one bitwidth but fail for another chosen by cost model.
- **Expected Issue**: Semantically incorrect truncation chosen due to cost

### Analysis

### Bug Triggering Analysis

The test case demonstrates the AbsIntrinsicPoisonFlagMismatch issue. When SLP vectorizer reduces bitwidth for abs intrinsics, it forces the poison flag to false (line 12598-12600 in the patch). However, this changes semantics when the original abs had poison flag true and the input value is the signed minimum of the reduced type.

Specifically:
- Original: `abs(i32 -32768, i1 true)` where -32768 is i16 INT_MIN when truncated
- With poison flag true: Could return poison (implementation-defined)
- After SLP reduction to i16: `abs(i16 -32768, i1 false)` (poison flag forced to false)
- Result: Always returns 32768, never poison

This semantic difference violates the principle that vectorization should preserve program behavior. The fix assumes setting poison flag to false is always safe, but it's not when the original could return poison for signed minimum values.

### Fix Weakness Analysis

The weakness in the fix is in lines 12598-12600:
```cpp
if (ID == Intrinsic::abs && It != MinBWs.end() &&
    It->second.first < DL->getTypeSizeInBits(CEI->getType()))
  ScalarArg = Builder.getFalse();
```

The assumption is: "if we reduce bitwidth for abs intrinsic, set poison flag to false to avoid returning poison for signed min". However, this changes semantics when:
1. Original abs had poison flag true
2. Input value equals signed minimum of reduced type (e.g., i32 -32768 → i16 -32768)
3. Original implementation would return poison for this case

The fix should either:
1. Not reduce bitwidth when abs has poison flag true and values could be signed min of reduced type
2. Preserve the original poison flag and accept potential poison semantics
3. Add more precise analysis to determine if values can be signed min of reduced type

Similar issues exist for smin/smax sign bit analysis and umin/umax masked value checks, but the abs poison flag issue is the most clear-cut semantic violation.
