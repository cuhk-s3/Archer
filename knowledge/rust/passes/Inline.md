## Patterns Not Well Handled

### Cross-crate inline cost model: assert, call, and intrinsic classification
The cross-crate inlinability cost model that feeds the Inline pass must charge terminators according to their actual leaf/CGU impact. Historical corrections show two distinct classifications: `Assert` terminators are statement-like and must not increment the call counter, while genuine `Call` and `TailCall` terminators remain real calls; separately, a `Call` whose callee resolves through `func.const_fn_def()` to a `rustc_intrinsic` definition does not make the function non-leaf because intrinsics have no body assigned to a CGU. The wrong models either charged asserts as calls, suppressing small assert-only leaf functions, or counted intrinsic-only calls as ordinary calls, suppressing intrinsic-only leaf functions. These are compile-time inlining-decision differences, not runtime miscompilation claims.
Preconditions: The callee is in another crate (dependency or sysroot) and is being considered by `cross_crate_inlinable` and then the Inline pass.; The callee's optimized MIR contains either an `Assert` terminator with no genuine calls (for example the divisor-nonzero assert for `a / b`) or only calls to definitions carrying `rustc_intrinsic`.; The call/statement threshold is restrictive enough that the old classification changes the inlinability result.; After removing assert cost from calls, the assert must still contribute statement cost.; Only calls whose callee resolves via `func.const_fn_def()` and has `sym::rustc_intrinsic` are exempt from the call count; ordinary calls still increment it.

### Reject tainted or not-yet-substituted callees before inlining
The Inline pass must reject callee bodies that are malformed by error recovery or not yet sufficiently substituted. ### Synthetic async-closure by-move bodies must be function-like, in mir_keys, and metadata-encoded

The historical omission treated `DefKind::SyntheticCoroutineBody` as non-function-like, omitted it from `mir_keys`, failed to encode/decode `coroutine_by_move_body_def_id` in metadata, returned false from `cross_crate_inlinable`, and excluded it from the symbol-mangling globally-shared-function set. As a result `optimized_mir` was not encoded for the synthetic body, the Inline pass could steal MIR without first ensuring `mir_inliner_callees`, causing a Steal ICE under `-Zinline-mir`, and cross-crate inlining could not recognize the body. The corrections make the def-kind function-like, add it to cross-crate inlinability and symbol-mangling global sharing, encode the by-move body def-id, and insert the synthetic body into `mir_keys`.

### Coroutine variant projection validation must use caller_body, not a substituted inline body
During MIR validation of inlined coroutine bodies, the TypeChecker must distinguish the possibly-substituted callee body under validation from the original caller body. ### Const-eval mentions must survive optimization-dependent Inline and dead-code elimination
Monomorphization collection must not depend on optimization-level-dependent dead-code elimination, including inlining that removes the sole syntactic use of an item with a failing post-monomorphization constant. The historical collector walked only used items after MIR optimization, so an optimized build could silently drop the only call/drop/coercion path to a failing `required_consts` and accept code that a no-opt build rejected. The correction records `MentionedItems` before optimizations and, in mention mode, recursively evaluates `required_consts` of mentioned items even when they are no longer used. The mention set is optimization-independent in intent, not a stable or soundness-critical API.
Preconditions: `MentionedItems` runs before optimization-level-dependent passes and is enabled even at opt-level 0.; The collector distinguishes `CollectionMode::UsedItems` from `CollectionMode::MentionedItems`; mention mode evaluates `required_consts` and recursively processes `body.mentioned_items` without producing used items.; Mention gathering mirrors collector visiting: `Call`, `Drop`, `InlineAsmOperand::SymFn`, unsizing/`DynStar`, `ReifyFnPointer`, and `ClosureFnPointer` casts.; `MentionedItem::Fn` and `MentionedItem::Closure` record a `Ty`, not a `DefId` plus args, because a generic/opaque/associated callee may only become a `FnDef` or `Closure` after monomorphization.; Used-item traversal records `used_mentioned_items` before monomorphizing so mention processing can skip items already fully visited as used items.
Pitfalls: Do not gather mentions only from constants whose type is already `ty::FnDef`; pre-monomorphization callees may be generic, opaque, or associated and may only become `FnDef` during monomorphization.; Do not classify every unsizing cast as vtable-producing; the array-to-slice/str case is excluded by `(Some(ty::Array(..)), Some(ty::Str | ty::Slice(..))) => false`.; Do not treat every remaining unsize as automatically a vtable; `visit_mentioned_item` still checks target trait/dyn-star versus source trait/dyn-star and is only interested in casts that produce a vtable.; Do not update `usage_map` for mention-only visits; the source says to update it only for used items because the usage-map logic does not like duplicate mixed mention/use entries.; Do not assert the mentioned set is stable or soundness-critical; it is optimization-independent in intent, not stable API.; Do not let test helper generics be inlined when the goal is to retain a generic mention; the test adds `#[inline(never)]` because inlining could monomorphize the generic helper.
Test strategy: Use UI revisions so the same source is compiled both ways: `//@revisions: noopt opt`, `//@ build-fail`, `//@[noopt] compile-flags: -Copt-level=0`, `//@[opt] compile-flags: -O`, and mark the same `E0080` on the const line for both revisions. Add focused cases for direct dead calls, `Drop`/move, fn-pointer reification, closure-to-fn-pointer, const-valued fn pointers, vtable-producing unsizing, inline asm `SymFn`, and callees hidden behind generic/opaque/associated types. Mark generic helpers `#[inline(never)]` so the test exercises mention gathering rather than accidental monomorphization through inlining. Require both revisions to fail with the same primary const-eval error, and keep a build-pass negative control for dead code that does not mention a failing const.
